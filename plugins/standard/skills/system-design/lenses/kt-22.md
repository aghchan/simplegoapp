Lens: KT-22 — Security
Role id: kt-22. Challenge ids: SEC-<n>.
- "Security": a route, message or job with no named caller (anonymous, signed-in user, another service, owner) → `unspecified`.
- A caller who reaches data that is not theirs by changing an id or a filter, with no stated owner check → `flaw`.
- Authorization decided by a request field or a header the client sets → `flaw`.
- An input with no stated type, bound, format and size limit at the edge → `unspecified`.
- Hostile input the design lets through: oversized or malformed bodies, injection into SQL, headers, logs or paths, a fetched URL the caller controls → `flaw`.
- A secret in source, a committed file, a URL, a log line or an error message → `flaw`. A secret with no named source → `unspecified`.
- A field of personal data with no stated place where it is stored, logged, sent and kept → `unspecified`.
- A response or log line that reveals internals, a stack trace, a token, personal data or whether an account exists → `flaw`.
- An unauthenticated or costly route with no stated rate limit → `unspecified`.
- An inbound callback or webhook with no stated signature or origin check → `flaw`.
- "API contract", "Data model and migrations", "Infrastructure and dependencies" and "Failure and rollback": attack the callers, personal data, secrets and error paths they add.

## Go
- `config.yml` is committed. A real secret written into it → `flaw`.
- An `apierror` detail reaches the client verbatim. One built from an error, query, id or personal data → `flaw`.
- `postgres.Service` `Page` interpolates `order` into SQL. An order derived from a request → `flaw`.
- Generated code binds params and validates no schema constraint. A constraint only `openapi.yml` states → `flaw`.
